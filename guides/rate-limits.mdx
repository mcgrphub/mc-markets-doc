MC OpenAPI applies traffic protection at the API Gateway. Treat HTTP **`429 Too Many Requests`** as the authoritative rate-limit signal.

<Note>
  The rate-limit key depends on the request stage and route configuration. Before authentication, a limiter can key by IP or path plus IP. After authentication, it can key by a trusted Access Key or UID. Do not assume every endpoint is limited only by Access Key.
</Note>

The fixed source does not define one limit value that applies to every public endpoint. Use the effective route configuration and observed responses for capacity planning.

## Recognize rate limiting

The AK/SK v2 protection layer returns this typical response:

```json
{
  "status": 429,
  "code": 429,
  "message": "请求过于频繁，请稍后重试"
}
```

Other gateway limiters can produce a different body. Clients should:

1. Check whether the HTTP status is `429`.
2. Record `message` for diagnostics when the response is JSON.
3. Avoid depending on fixed `42901`, `msg`, or `success` fields.

## Exponential backoff with jitter

```python
import random
import time


def call_with_backoff(send_request, *, max_retries=6, base=1.0, cap=30.0):
    for attempt in range(max_retries):
        response = send_request()
        if response.status_code != 429:
            return response

        delay = min(cap, base * (2**attempt)) + random.uniform(0, 0.5)
        time.sleep(delay)

    raise RuntimeError("Exceeded max retries after repeated HTTP 429 responses")
```

```javascript
async function callWithBackoff(
  sendRequest,
  { maxRetries = 6, base = 1000, cap = 30_000 } = {},
) {
  for (let attempt = 0; attempt < maxRetries; attempt += 1) {
    const response = await sendRequest();
    if (response.status !== 429) return response;

    const delay = Math.min(cap, base * 2 ** attempt)
      + Math.floor(Math.random() * 500);
    await new Promise((resolve) => setTimeout(resolve, delay));
  }
  throw new Error("Exceeded max retries after repeated HTTP 429 responses");
}
```

## Request guidance

- Reduce unnecessary polling and cache slow-changing currency and exchange-rate data.
- Persist pagination progress so a failed job can resume from the unfinished page.
- Generate a new timestamp, nonce, and signature for every retry.
- Back off on transient `500`, `502`, and `503` responses, but do not automatically retry parameter or permission errors.
- Log request time, path, HTTP status, and correlation ID; never log the Secret Key.
