## 入门

<AccordionGroup>
  <Accordion title="如何获取 Access Key 与 Secret Key?">
    登录 MC 账号,打开 **API 管理**。创建新 Key,选择需要的权限(`READ`、`TRADE`、`WITHDRAW`),立即复制 Access Key 与 Secret Key—Secret Key 仅显示一次。完整步骤见 [认证](/zh/authentication)。
  </Accordion>

  <Accordion title="网关地址是什么?">
    生产网关为 `https://gateway.mcconnects.com`。所有 OpenAPI 请求均通过该地址访问。详见 [基础 URL](/zh/api-reference/base-url)。
  </Accordion>

  <Accordion title="每个接口需要什么权限?">
    - `READ` — 大多查询接口(交易、持仓、汇率、币种元数据、PoR)。
    - `TRADE` — 下单、撤单，以及当前公开的理财申购和赎回接口。
    - `WITHDRAW` — API Key 支持的权限类型；当前公开 Spec 中没有要求该权限的接口。

    具体权限在 [API 参考](/zh/api-reference/overview) 的接口页中标注。
  </Accordion>
</AccordionGroup>

## 认证

<AccordionGroup>
  <Accordion title="到底签名什么?">
    待签名字符串包含方法、URI、可选 query、参与签名的头（`x-access-key` / `x-nonce` / `x-timestamp`）、时间戳、nonce，以及（`POST`/`PUT`/`PATCH`/`DELETE` 非空 body 时）body 的 SHA-256 小写 hex。`X-Signature` 为 HMAC-SHA256 的 **Base64**（不是 hex）。每次请求须带新的 `X-Nonce`（**UUID v4**，或 ≥32 位十六进制）。完整规则见 [认证](/zh/authentication)。
  </Accordion>

  <Accordion title="返回签名无效怎么办?">
    按可能性排序:

    1. 待签名字符串缺少 `X-Nonce` 或（非空 `POST`/`PUT`/`PATCH`/`DELETE` 时）body SHA-256。
    2. 待签名字符串与网关预期不一致——打印并逐字节对比（含 `X-Nonce` 值是否与头一致）。
    3. 签名时使用的 body 与实际发送的 body 不一致（多余空格、重排 JSON）。序列化一次，两处复用同一字节。
    4. 把 Access Key 当作 Secret Key。
    5. query 参数未按 key 升序排序，或出现重复 query key。
    6. `X-Nonce` 不是 UUID v4，也不是 ≥32 位十六进制。

    另见 [排障](/zh/help/troubleshooting)。
  </Accordion>

  <Accordion title="返回时间戳无效或已过期怎么办?">
    网关通常返回 HTTP `401`，并在 `message` 中说明时间戳错误。本机时钟与网关偏离时，`X-Timestamp` 必须改为当前 UTC **毫秒**（非秒）并使用 NTP 同步。
  </Accordion>

  <Accordion title="如何无停机轮换密钥?">
    可以。创建一把相同权限的新 Key,部署后在后台禁用旧 Key。两把 Key 在旧 Key 禁用前同时有效。
  </Accordion>
</AccordionGroup>

## 请求与分页

<AccordionGroup>
  <Accordion title="哪些接口返回分页响应?">
    大多数业务列表使用请求 `current` / `size`，并返回 `records`、`total`、`current`、`size`、`pages`、`hasPrevious`、`hasNext`。行情排行榜使用 `page` / `pageSize` 和 `items`。见 [分页](/zh/concepts/pagination)。
  </Accordion>

  <Accordion title="每页最多可以请求多少条?">
    没有适用于所有接口的统一文档值。请使用具体接口 schema 中的 `size` 或 `pageSize` 限制；未声明时从较小值开始，并根据响应和限流情况调整。
  </Accordion>

  <Accordion title="如何获取实时更新?">
    MC OpenAPI 目前不提供 Webhook 或事件推送。使用 [轮询模式](/zh/guides/webhooks) 高效检测新活动。
  </Accordion>
</AccordionGroup>

## 数据模型

<AccordionGroup>
  <Accordion title="什么是储备金证明(PoRv2)?">
    基于 Merkle 树的用户资产快照。调用 `GET /openapi/v1/mc-account/fund/account/por` 获取你的快照与审计路径。完整 schema 见 [API 参考](/zh/api-reference/overview) 侧边栏 **Account** 下的资金账户相关 operation。
  </Accordion>

  <Accordion title="v1 与 v2 接口差异?">
    当前公开 Spec 同时包含上下文用户持仓 `/fund/account/spot/positions/v2`，以及按 `spotId` 查询的 `/fund/account/spot-account/positions`；资金费记录路径为 `/funding-fee-record/page/v2`。它们不是可以任意互换的版本别名，请按 [API 参考](/zh/api-reference/overview) 选择接口。
  </Accordion>

  <Accordion title="数字字段是数字还是字符串?">
    字段类型以具体接口 schema 为准：部分字段是 JSON `number`，部分接口同时提供 `*Display` 或字符串字段。计算时使用十进制库（Python `Decimal`、JavaScript `bignumber.js`、Java `BigDecimal`），不要假定所有数值都是同一种 JSON 类型。
  </Accordion>
</AccordionGroup>

## 运维

<AccordionGroup>
  <Accordion title="有官方 SDK 吗?">
    暂无。Python、Node.js、Java、Go 的开箱即用客户端见 [代码示例](/zh/guides/sdks)。
  </Accordion>

  <Accordion title="频率限制如何实施?">
    限流键取决于鉴权阶段和路由配置，可能使用 IP、路径加 IP、Access Key 或 UID。客户端应以 HTTP `429` 为准，不要依赖固定业务码。退避策略见 [频率限制](/zh/guides/rate-limits)。
  </Accordion>

  <Accordion title="如何提 Bug 或需求?">
    联系 MC 支持,附上:描述、受影响接口、失败请求的时间戳,如可能包含响应体(隐去 Secret Key)。
  </Accordion>
</AccordionGroup>
