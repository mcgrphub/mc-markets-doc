将本指南作为请求失败时的决策树。始终**同时**检查 HTTP 状态码与 JSON 信封中的 `code`。

## HTTP 401 — 签名或时间戳问题

```json
{ "status": 401, "code": 401, "message": "签名无效" }
```

### 检查清单

- **签名校验。** 确认已携带新的 `X-Nonce`（**UUID v4**，或 ≥32 位十六进制），且待签名字符串含 `SIGNED_HEADERS`（含 `x-nonce`）、`TIMESTAMP`、`NONCE`；头中的 nonce 须与签名字符串完全一致。`POST`/`PUT`/`PATCH`/`DELETE` 非空 body 时追加 body SHA-256 小写 hex。
- **nonce 格式与复用。** 非 UUID v4 且非 ≥32 位 hex → `非法 nonce 格式`；同一 Access Key 下复用仍在窗口内的 nonce → `请求重放`。
- **无 query 时不要空行。** 无 query 时整行省略 `QUERY_STRING`，不要插入空白行。
- **body 一致。** JSON body 序列化一次，签名与发送复用同一字节。
- **query 排序。** 使用解码后的逻辑参数名和值，按 key 升序以 `key=value` 和 `&` 拼接；发送 URL 时再编码。禁止重复 query key。
- **方法/路径大小写。** 方法大写（`GET`，不是 `get`）。路径为网关可见路径，不包含 Base URL。
- **用对密钥。** `X-Access-Key` 为 Access Key，签名用 Secret Key。
- **摘要格式。** `X-Signature` 为 HMAC-SHA256 的 **Base64**（含 padding），不是小写 hex。

```json
{ "status": 401, "code": 401, "message": "时间戳无效或已过期" }
```

- `X-Timestamp` 为当前 **毫秒**（13 位，如 `1731657600000`），非秒。
- 使用 NTP 同步本机时钟。时间戳必须在服务器时间 ±10 分钟内。
- 批量调用时，为每次调用重新生成时间戳与 **nonce**（每次新的 UUID v4 或 ≥32 位 hex）。

## HTTP 401 — 权限不足

```json
{ "status": 401, "code": 401, "message": "没有访问该接口的权限" }
```

- Access Key 存在且签名正确,但无对应权限。
- 在 MC 控制台 **API 管理** 中为 Key 添加 `READ`/`TRADE`/`WITHDRAW`。
- 每个接口页均注明需要的权限:[API 参考](/zh/api-reference/overview)。

## HTTP 404 — 接口或资源不存在

- 对照 [API 参考](/zh/api-reference/overview) 核对完整路径,均以 `/openapi/v1/...` 开头,大小写敏感。
- 检查路径参数(`{id}`、`{symbolType}`、`{baseCurrency}`...)——必须 URL 安全且对应真实资源。
- 已删除的资源(如下架币种)对认证请求仍返回 `404`。

## HTTP 400 — 请求格式错误

```json
{
  "status": 400,
  "message": "Invalid request parameter",
  "code": "1000005",
  "codeKey": "PARAM_ERROR",
  "params": {},
  "localizedMessage": "Invalid request parameter",
  "data": null,
  "success": false
}
```

- 带 JSON body 的 POST/PUT 缺少 `Content-Type: application/json`。
- body 缺少必填字段,或类型不匹配(如对字符串字段传了数字)。
- 枚举值(权限、币种类型、币种)不在允许集内——对照接口页枚举。

## HTTP 429 — 频率限制

```json
{ "status": 429, "code": 429, "message": "请求过于频繁，请稍后重试" }
```

- 指数退避 \+ 抖动,参阅 [频率限制](/zh/guides/rate-limits) 中可拷贝的重试封装。
- 以 HTTP `429` 为限流判断依据；其他网关限流组件的响应体可能不同。
- 常规负载下仍频繁命中时，降低轮询频率并记录路径、时间和 correlation ID。

## HTTP 5xx — 网关错误

- `500`/`502`/`503` 属瞬时错误。使用与 `429` 相同的退避。
- 若某个接口持续 `5xx`,记录请求时间戳与 correlation 头,联系支持。

## HTTP 200 下的业务错误

不要假定 `200 OK` 就是成功。始终检查 `code`:

```json
{
  "status": 200,
  "message": "Insufficient balance",
  "code": "2004003",
  "codeKey": "ACCOUNT_BALANCE_INSUFFICIENT",
  "params": {},
  "localizedMessage": "Insufficient balance",
  "data": null,
  "success": false
}
```

常见类别:

- 理财账户申购/赎回时余额或限额不足。
- 交易接口中币种暂停或已下架。
- `/openapi/v1/mc-account/fund/account/por` 当前窗口的 PoR 快照尚未生成。

## 提交调试信息清单

请在提交支持工单时附上以下信息,可大幅缩短定位时间:

1. **Access Key ID** — 仅公开标识,绝不提供 Secret Key。
2. **时间戳** — 失败请求的 `X-Timestamp`。
3. **含 query 的完整路径。**
4. **响应体**(隐去 Secret Key,其他保留)。
5. **待签名字符串**（包含 query、签名头、时间戳、nonce，以及适用时的 body 哈希；保留末尾换行）。

<Warning>
  向任何人求助时都不要共享 Secret Key。若 Secret Key 已暴露,立即禁用并新建 Key。
</Warning>
