MC OpenAPI 在 API 网关执行频率保护。客户端应以 HTTP **`429 Too Many Requests`** 作为限流的权威信号。

<Note>
  限流维度取决于请求所处阶段和路由配置。鉴权前可能按 IP 或路径加 IP 计数；鉴权后可按可信 Access Key 或 UID 计数。不要假定所有接口只按 Access Key 限流。
</Note>

当前固定源码没有提供适用于所有公开接口的统一限额数字。调用频率应以具体路由配置和实际响应为准。

## 识别限流

AK/SK v2 保护层返回的典型响应为：

```json
{
  "status": 429,
  "code": 429,
  "message": "请求过于频繁，请稍后重试"
}
```

网关中的其他限流组件可能生成不同的响应体。因此客户端应：

1. 首先检查 HTTP 状态是否为 `429`。
2. 如果响应是 JSON，可记录 `message` 作为诊断信息。
3. 不要依赖固定的 `42901`、`msg` 或 `success` 字段。

## 带抖动的指数退避

```python
import random
import time


def call_with_backoff(send_request, *, max_retries=6, base=1.0, cap=30.0):
    for attempt in range(max_retries):
        response = send_request()
        if response.status_code != 429:
            return response

        delay = min(cap, base * (2**attempt)) + random.uniform(0, 0.5)
        time.sleep(delay)

    raise RuntimeError("Exceeded max retries after repeated HTTP 429 responses")
```

```javascript
async function callWithBackoff(
  sendRequest,
  { maxRetries = 6, base = 1000, cap = 30_000 } = {},
) {
  for (let attempt = 0; attempt < maxRetries; attempt += 1) {
    const response = await sendRequest();
    if (response.status !== 429) return response;

    const delay = Math.min(cap, base * 2 ** attempt)
      + Math.floor(Math.random() * 500);
    await new Promise((resolve) => setTimeout(resolve, delay));
  }
  throw new Error("Exceeded max retries after repeated HTTP 429 responses");
}
```

## 调用建议

- 减少不必要的轮询，并缓存币种、汇率等慢变数据。
- 分页读取时保存进度，失败后从未完成页继续。
- 每次重试都重新生成时间戳、nonce 和签名。
- 对瞬时 `500`、`502`、`503` 也可退避，但不要自动重试参数错误或权限错误。
- 日志中记录请求时间、路径、HTTP 状态和 correlation ID；不要记录 Secret Key。
