## Getting started

<AccordionGroup>
  <Accordion title="How do I get an Access Key and Secret Key?">
    Sign in to your MC account and open **API Management**. Create a new key, choose the permissions you need (`READ`, `TRADE`, `WITHDRAW`), and copy both the Access Key and the Secret Key immediately — the Secret Key is shown only once. Full walkthrough: [Authentication](/authentication#creating-api-keys).
  </Accordion>

  <Accordion title="What is the gateway URL?">
    The production gateway is `https://gateway.mcconnects.com`. All OpenAPI requests go through this host. See [Base URL](/api-reference/base-url).
  </Accordion>

  <Accordion title="Which permission does an endpoint require?">
    - `READ` — most query endpoints (transactions, positions, exchange rates, symbol metadata, PoR snapshots).
    - `TRADE` — order operations and the currently public Finance deposit and redemption endpoints.
    - `WITHDRAW` — an available API Key scope; no endpoint in the current public Specs requires it.

    The required scope is listed on each endpoint page under [API Reference](/api-reference/overview).
  </Accordion>
</AccordionGroup>

## Authentication

<AccordionGroup>
  <Accordion title="What exactly do I sign?">
    The string to sign includes method, URI, optional query, signed headers (`x-access-key` / `x-nonce` / `x-timestamp`), timestamp, nonce, and (for non-empty `POST`/`PUT`/`PATCH`/`DELETE` bodies) the lowercase SHA-256 hex of the raw body. Put the HMAC-SHA256 digest in `X-Signature` as **Base64** (not hex). Every request needs a new `X-Nonce` (**UUID v4**, or ≥32 hex characters). Full rules: [Authentication](/authentication).
  </Accordion>

  <Accordion title="I get an invalid signature. What's wrong?">
    In order of likelihood:

    1. The string to sign is missing `X-Nonce` or (for non-empty `POST`/`PUT`/`PATCH`/`DELETE`) the body SHA-256.
    2. The string to sign does not match what the gateway expects — print it and compare byte-for-byte (including whether `X-Nonce` matches the header).
    3. You signed different body bytes than you sent (extra whitespace, reordered JSON). Serialize once and reuse the exact bytes.
    4. You used the Access Key in place of the Secret Key.
    5. Query parameters are not sorted by key ascending, or a query key is repeated.
    6. `X-Nonce` is neither UUID v4 nor ≥32 hex characters.

    See also [Troubleshooting](/help/troubleshooting).
  </Accordion>

  <Accordion title="I get a timestamp invalid or expired error. What's wrong?">
    The gateway normally returns HTTP `401` and describes the timestamp problem in `message`. Use current UTC time in **milliseconds**, not seconds, and synchronize the machine clock with NTP.
  </Accordion>

  <Accordion title="Can I rotate keys without downtime?">
    Yes. Create a new key with the same permissions, deploy it, then disable the old key in the console. Both keys are valid concurrently until you disable the old one.
  </Accordion>
</AccordionGroup>

## Requests and pagination

<AccordionGroup>
  <Accordion title="Which endpoints return a paginated response?">
    Most business lists request `current` / `size` and return `records`, `total`, `current`, `size`, `pages`, `hasPrevious`, and `hasNext`. Market rankings use `page` / `pageSize` and `items`. See [Pagination](/concepts/pagination).
  </Accordion>

  <Accordion title="How many records can I request per page?">
    There is no single documented limit for every endpoint. Use the `size` or `pageSize` constraint in the endpoint schema. If none is declared, start with a modest value and adjust for responses and rate limiting.
  </Accordion>

  <Accordion title="How do I get real-time updates?">
    MC OpenAPI does not currently deliver webhooks or push events. Use the [polling patterns](/guides/webhooks) for detecting new activity efficiently.
  </Accordion>
</AccordionGroup>

## Data model

<AccordionGroup>
  <Accordion title="What is Proof of Reserves (PoRv2)?">
    A per-user Merkle-tree snapshot of assets held on the platform. Call `GET /openapi/v1/mc-account/fund/account/por` to fetch your snapshot and audit path. See the fund-account operations under **Account** in the [API Reference](/api-reference/overview) for the full response schema.
  </Accordion>

  <Accordion title="What is the difference between v1 and v2 endpoints?">
    The current public Specs include `/fund/account/spot/positions/v2` for the context user and `/fund/account/spot-account/positions` for a specified `spotId`; funding-fee records use `/funding-fee-record/page/v2`. These are not interchangeable version aliases. Choose the operation from the [API Reference](/api-reference/overview).
  </Accordion>

  <Accordion title="Are numeric fields returned as numbers or strings?">
    Follow each endpoint schema. Some fields are JSON `number`; some endpoints also provide string or `*Display` fields. Use a decimal library (Python `Decimal`, JavaScript `bignumber.js`, Java `BigDecimal`) for calculations, and do not assume one JSON type for every numeric value.
  </Accordion>
</AccordionGroup>

## Operational

<AccordionGroup>
  <Accordion title="Are there official SDKs?">
    Not yet. Copy-paste-ready client snippets for Python, Node.js, Java, and Go are on [Code Samples](/guides/sdks).
  </Accordion>

  <Accordion title="How are rate limits enforced?">
    The key depends on the authentication stage and route configuration and can be IP, path plus IP, Access Key, or UID. Treat HTTP `429` as authoritative instead of depending on a fixed business code. See [Rate Limits](/guides/rate-limits).
  </Accordion>

  <Accordion title="Where do I report a bug or request a feature?">
    Contact MC support with a description of the issue, the affected endpoint, the timestamp of a failing request, and — if possible — the response body (with Secret Key redacted).
  </Accordion>
</AccordionGroup>
